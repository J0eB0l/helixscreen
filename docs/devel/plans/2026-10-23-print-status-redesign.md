# Print Status Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo, CLAUDE.md § Verification Cadence overrides both skills: each task runs only its own tags, there is no per-task review, and the review, mutation run, screenshots and land-gate happen once at the finish (Task 8).

**Goal:** Replace the print status panel's right column with D3: a job tile (pre-print checklist or live preview), a printer tile with chips, leader lines and glows on the printer picture, and a full-width strip with progress and Pause/Tune/More/Cancel, at every supported size.

**Architecture:** There are three pure decisions with unit tests:
- the callout engine, extended (`include/callout_layout.h`)
- the chip content (`include/print_status_chips.h`)
- the checklist rows and tile arrangement (`include/preprint_checklist.h`, `include/print_status_tile_layout.h`)

`CalloutPresenter` (`include/callout_presenter.h`) is the one LVGL-side applier, and both the home printer-image widget and the panel use it. `PrintStatusPanel` copies decisions into subjects, and the XML binds to them.

**Tech Stack:** C++17, LVGL 9.5, helix-xml, Catch2.

**Spec:** `docs/devel/plans/2026-10-23-print-status-redesign-design.md` (read it first). The mockups are in `.superpowers/brainstorm/3044032-1792793919/content/d3-lines-v2.html` on thelio, generated by `/tmp/claude-1000/-home-pbrown-Code-Printing-helixscreen/638c186d-317f-45f9-b5b9-5622dd99df3d/scratchpad/gen_small.py`.

**Branch / tree:** `feature/print-status-redesign`, `.worktrees/print-status-redesign`. The interface headers are already committed there and pass `scripts/syntax_check.py`: `include/callout_layout.h` (moved from `src/ui/panel_widgets/`, new kinds and fields), `include/callout_presenter.h`, `include/preprint_checklist.h`, `include/print_status_chips.h`, `include/print_status_tile_layout.h`. Implement against them, and change a signature only with a note in the commit body.

## Global Constraints

- Declarative UI (`.claude/rules/declarative-ui.md`): visibility, text and styles come from subjects and `bind_*`. No `lv_obj_add_flag` or `lv_label_set_text` for state. `lv_obj_set_pos` is allowed only inside `CalloutPresenter` (measured layout, a structural exception).
- Threading (`.claude/rules/threading.md`): `PrintStartCollector` state is read under its mutex and published to subjects only on the main thread (`ui_queue_update`).
- Design tokens only. Amber = the theme's warning token. Chips are 50% opaque (`style_bg_opa="50%"` on the chip style). No raw colors.
- US English strings, wrapped in `lv_tr`, with translation keys added per `docs/devel/TRANSLATION_SYSTEM.md`.
- Constant names `kCamelCase`. No RTTI and no exceptions in shared code.
- No vendor names in the panel or the chip logic.
- Comments describe the code as it is now. No archaeology.
- Never invent future pre-print steps.

## Review Focus

1. **A printer with no `regions.json` entry or a custom photo.** The tile must draw Docked: chips at the edges, no lines, no glows, nothing missing. Pinned in Task 1 (`untagged image docks every chip`) and Task 6 (screenshot with a custom image).
2. **A tagged image that lacks `light` or `chamber` (66 of ~85 lack light).** That chip docks with no line while the others keep their lines. Pinned in Task 1 (`missing anchor docks only that chip`).
3. **The phase switch mid-layout.** `preparing_visible` 1→0 while the panel is open must swap the job tile, re-run the callout layout once, and leave no stale glow. Pinned in Task 5 (`phase switch relayouts and clears pre-print glows`).
4. **Multi-tool printers.** The nozzle chip must name the active tool, and a tool change must update it without a relayout storm. Pinned in Task 3 (`heater_chip carries tool badge text`) and Task 5.
5. **Print outcome set (complete, cancelled, error).** Cancel becomes Reprint, the checklist never reappears, and chips keep updating. Pinned in Task 5 (`outcome shows reprint and keeps preview`).

### Task 1: Callout engine: expendable chips, partial anchors, pinned leaders

**Files:**
- Modify: `include/callout_layout.h` (`compute_callout_layout`, `callout_detail::try_line_modes`, the Pinned loop)
- Modify: `src/ui/panel_widgets/printer_image_widget.cpp`, `src/ui/ui_overlay_printer_image_tagger.cpp` (only switch cases for the new kinds, if the compiler asks)
- Test: `tests/unit/test_callout_layout.cpp` (`[printer_image][callout_layout]`)

**Interfaces:**
- Produces, already declared: `CalloutKind::{HotendFan, AuxFan, SpeedFlow}`, `kCalloutKindCount`, `CalloutChipIn::expendable`, `CalloutLayoutInput::leader_min_distance`, `CalloutLayout::dropped`.

The behavior to add:
- **Partial anchors.** `try_line_modes` currently refuses when any chip lacks an anchor. Change it: chips with anchors go through line modes as now, and chips without one go to `place_docked` in the space the line modes leave (the band opposite the image's shift, else the bottom row). Fit is still tested against the budget.
- **Expendable first.** When neither line mode fits, and before falling to Pinned, retry the line modes with the expendable chips left out of both budget and active. In the Pinned loop, a column too tall to stack drops an expendable chip (recorded in `dropped`) before it docks a non-expendable one. Nozzle and Toolhead are never dropped.
- **Pinned leaders.** A pinned chip gets `has_line = true` and its line points when the distance between its centre and its point is more than `leader_min_distance`. With 0, pinned chips stay line-free, as the home widget has them now.

  - `missing anchor docks only that chip`: tagged, area 342x270, image 645x908, `chip_h=22`, `gap=4`, `min_line=8`. Chips: Nozzle (0.441,0.36), Bed (0.346,0.382), Light with no anchor, SpeedFlow with no anchor. `mode` is BothSides or OneSide. Nozzle and Bed have `has_line`. Light and SpeedFlow have `!has_line` and rects inside the area that don't overlap the image rect.
  - `expendable chips drop before the image goes pinned`: an area where the full budget fails the line modes but fits without the two expendable fans. `mode != Pinned`, and `dropped` contains both fan kinds.
  - `pinned drops expendable before docking`: a 150x190 area with 7 pinned chips, 2 of them expendable. `dropped` holds only expendable kinds, and no non-expendable chip is in the docked row.
  - `pinned chip draws a leader only past leader_min_distance`: two chips on the same anchor, `leader_min_distance=12`. The one slid more than 12 px has `has_line`, and the one left on its point does not.
  - `leader_min_distance 0 keeps pinned line-free`: the same input with 0, so no chip has `has_line`.

### Task 3: Pure models: chips, checklist, tile arrangement

**Files:**

**Interfaces:**
- Produces: the functions declared in `include/print_status_chips.h`, `include/preprint_checklist.h` and `include/print_status_tile_layout.h`. Also `const char* print_start_phase_step_label(PrintStartPhase)`, which returns `lv_tr` labels with no ellipsis: "Homing", "Heating bed", "Heat soak", "Heating nozzle", "Quad gantry level", "Z tilt", "Bed mesh", "Cleaning nozzle", "Purge". It returns "" for IDLE, INITIALIZING and COMPLETE.

Rules the code must follow (from the spec):
- `heater_chip`:
  - Text is `"220°"` normally and `"184 / 220°"` while Heating or Cooling, with `" · 5%"` appended when `show_power` and the duty is non-empty.
  - Tone is Active while Heating before printing, and Warn when `printing` and the heater is Heating or Cooling. Otherwise the tone is Normal.
  - `progress_pct` is `(current - start) / (target - start)` clamped to 0..100 while Heating, else -1.
  - `glow` is true while target > 0.
  - Not shown when `!present`, or when target is 0 and current < 40 °C.
- `fan_chip`:
  - Text is `"30%"`, prefixed with `Part`, `HE` or `Aux` when `labeled`.
  - Part fan > 0 is Active with glow.
  - pct 0 is Dim and expendable. Hotend `automatic` is expendable.
  - Not shown when `!present`.
- `speed_flow_chip`: text `speed_text + " · " + flow_text`. Warn when either factor is not 100, else Normal and expendable.
- `light_chip`: shown when `controllable`. On is Active with glow. Off is Dim and expendable.
- `build_preprint_checklist`: the rules are in the header comment.
- `decide_print_status_tile_layout`:
  - Stacked when `content_h > content_w` and `content_h >= 500`, else SideBySide.
  - `strip_stacked` when Stacked or `content_w < 400`.
  - The job and printer tiles split the width evenly (SideBySide) or take 236/196 of the height in proportion (Stacked).
  - `checklist_compact` when the job tile is narrower than 180 or shorter than 170.
